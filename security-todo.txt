C1. service_role key used for ALL backend DB access (ADR-009 violated)
----------------------------------------------------------------------------
Files:
- backend/app/config.py
  * Add `supabase_anon_key: str` setting (RLS-enforced client key).
- backend/app/database.py
  * `get_supabase()` -> create_client(url, anon_key)  [RLS-enforced, no session]
  * `get_user_supabase()` -> anon-key client + caller JWT attached via
    `client.postgrest.auth(token)` [RLS-enforced as the authenticated user]
  * `get_service_role_supabase()` -> create_client(url, service_role_key)
    [ONLY for /checkout create_order + decrement/increment RPCs]
- backend/app/utils/security.py
  * Add `get_access_token` dependency (raw bearer token) used by
    get_user_supabase. Switch the /auth/v1/user apikey from service_role to
    anon key (service_role must not be used outside /checkout).
- backend/app/routes/checkout.py
  * Inject `get_user_supabase` (reads) + `get_service_role_supabase`
    (transaction) instead of a single service_role client.
- backend/app/routes/admin.py
  * Use `get_user_supabase` on every endpoint. `_assert_admin` keeps its
    profile-role read but now runs through RLS (user reads own row; is_admin
    policy gates admin visibility).
  * Approve/reject: replace direct `profiles.update({role})` with
    `admin_set_profile_role` SECURITY DEFINER RPC (checks is_admin() inside;
    profiles.role column is not API-writable via column grants).
  * Cancel order: replace item read + per-item `increment_stock_inventory`
    loop + status update with `admin_cancel_order` SECURITY DEFINER RPC
    (admin-guarded, atomic restock + status change). Non-cancel status
    updates stay as RLS-gated `orders.update`.
- backend/app/adapters/order_intake.py
  * Accept the user client for reads and the service_role client for the
    transaction RPC.
- supabase/migrations/004_security_hardening.sql (NEW)
  * Add `admin_set_profile_role` + `admin_cancel_order` SECURITY DEFINER
    functions, granted to authenticated only (self-guarded by is_admin()).
- backend/tests/test_checkout.py, test_admin.py, conftest.py
  * Override the new dependencies; update cancel-order test to the RPC.

C3. Stock validation check-then-act outside transaction (TOCTOU -> 500)
----------------------------------------------------------------------------
Files:
- supabase/migrations/004_security_hardening.sql (NEW)
  * Rewrite `create_order` (same signature, existing service_role-only grant
    preserved):
      - validate p_items non-empty and each quantity > 0 (RAISE otherwise)
      - lock product rows `SELECT ... FOR UPDATE` and re-check availability
        INSIDE the transaction
      - if any item short/unknown -> RETURN structured result
        `{commit:false, insufficient_stock:true, out_of_stock:[{product_id,
        title, available, requested}]}` (no order inserted, nothing rolled back)
      - otherwise insert order + order_items, then decrement each via
        `decrement_stock_inventory` (unchanged atomic guard) and return
        `{commit:true, order_id, readable_order_id}`
- backend/app/adapters/stock.py
  * Move `InsufficientStockError` here (shared by order_intake + txn).
- backend/app/adapters/txn.py
  * Inspect RPC result: if `insufficient_stock` -> raise
    InsufficientStockError(out_of_stock mapped to StockErrorItem); generic
    500 otherwise (no detail leak).
- backend/app/adapters/order_intake.py
  * Keep pre-check ONLY as a UX hint (never source of truth).
- backend/tests/test_adapters_txn.py, test_checkout.py
  * Add coverage: RPC returning insufficient_stock -> 400 out_of_stock[];
    existing generic-500 tests kept (behavior unchanged for true failures).
